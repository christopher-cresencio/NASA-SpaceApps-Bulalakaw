# Meeting Minutes: Team Bulalakaw (NASA International Space Apps Challenge)
**Date:** October 16, 2026  
**Project:** Junior Astronaut Mission Trainer  
**Target Platform:** Web-based Interactive Simulation Game  
**Target Audience:** Students & Young Learners (~12 years old)  

---

## 1. Challenge & Mission Objective
* **Selected Challenge:** "Build a Junior Astronaut Mission Trainer" (unanimous team vote: 6/6).
* **Core Problem:** Most space STEM content either oversimplifies real mission engineering trade-offs or is too complex and dry for younger learners.
* **Our Solution:** A browser-based outpost management simulation focused on **Mars**. The player acts as the outpost commander, balancing four tightly coupled life-critical resources over a series of mission days (Sols). Random environmental and mechanical events force difficult decisions. The game concludes with a breakdown explaining the real science and engineering behind their success or failure.
* **Scope Baseline:** Primary focus is Mars. Lunar outpost is strictly a secondary stretch goal if time permits.

## 3. Team Roles & Responsibilities

### A. Research and Design Team (Leads: Denise Catamora & Raindel Devilla)
1. **Architect (Game Mechanics & Systems Planning):**
   * Formulate the core loop: turn/day progression, daily resource consumption rates, and baseline allocation rules.
   * Model the 4-way resource tension:
     * **Power:** Generated by solar panels and stored in batteries; powers Life Support, Food Production, and Active Shielding. Degraded by dust accumulation and Martian night.
     * **Life Support (O₂ & H₂O):** Continuous power drain to recycle air and water. If power fails, life support margins drop rapidly.
     * **Food Production:** Hydroponics/aeroponics requiring steady power and water. Crop cycles take multiple turns; neglect causes delayed food shortages.
     * **Radiation Shielding:** Passive (regolith mass) and active systems protecting crew from background galactic cosmic rays (GCRs) and solar particle events (SPEs).
   * Define clear, measurable win/loss thresholds (e.g., crew survival for 30 Sols vs. critical system failure).

2. **Research & Data Organization:**
   * Source real NASA baseline figures (e.g., daily O₂/H₂O consumption per astronaut, solar irradiance on Mars [~590 W/m² vs ~1361 W/m² on Earth], Martian dust storm impacts, and radiation dosage in millisieverts).
   * Structure data into a shared reference format that directly maps to game parameters (base values, trade-off multipliers, and accompanying educational factoids).
   * Draft concise, age-appropriate educational explanations (1–2 sentences) explaining the real NASA science behind each event and outcome.

3. **Visuals (Front-End Design & UI Assets):**
   * Design a clean, responsive layout optimized for desktop and mobile browsers.
   * Produce visual assets:
     * Resource gauges/meters (color-coded status bars for Power, O₂, H₂O, Food, Radiation).
     * Outpost status display (modular base schematic or isometric cross-section showing operational states).
     * Action buttons, alert badges, and event illustration cards.

---

### B. Core Programming Team (Leads: Kent Chrysler Sabado, Red Colby, Jhon Rey Oquendo)
1. **Core Simulation & Game Logic:**
   * Implement the state machine managing mission phases (Briefing, Day Loop, Event Resolution, Debrief).
   * Write the mathematical resource simulation engine calculating turn-by-turn deltas:
     $$\text{Resource}_{\text{Sol } n+1} = \text{Resource}_{\text{Sol } n} + \text{Production} - \text{Consumption} \pm \Delta_{\text{Event}}$$
   * Implement random event triggers with condition-based probability (e.g., dust storms reduce solar output by 70%, forcing reliance on stored battery reserves).

2. **Front-End & UI Implementation:**
   * Build the UI screens using responsive web standards (HTML5/CSS3/JavaScript or lightweight framework).
   * Render real-time visual feedback: animated gauge adjustments, alarm states when resources hit critical red zones (<20%), and interactive decision modals for events.
   * Guarantee smooth cross-browser performance and touch-friendly controls on mobile devices.

3. **Data Integration, Polish & Deployment:**
   * Connect the game engine to external data files (JSON/YAML) so research updates reflect immediately without changing simulation code.
   * Integrate audio-visual effects (subtle sci-fi UI clicks, alarm sirens, dust storm overlays).
   * Conduct iterative playtesting to calibrate difficulty (ensuring it is challenging yet beatable for 12-year-olds).
   * Deploy to a fast, reliable public web host (e.g., GitHub Pages, Vercel, or Firebase Hosting) ready for judging.
